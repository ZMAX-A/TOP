# M8.2 质量告警 Webhook 可靠投递基础

## 目标

为 M8.1 的质量变化信号建立独立、安全且可审计的外部投递基础。首个垂直切片完成项目级 Webhook 配置、
测试事件、持久化投递、签名和失败重试；真实质量状态变化的自动触发将在该基础验证稳定后接入，避免把通知
副作用混入质量分析 GET 请求或已有 Run/Celery Outbox。

## 已实现

- `GET/PATCH /api/v1/projects/{project_id}/quality/webhook` 读取和更新项目配置；读取结果只返回脱敏目标，更新
  需要 `project:manage`，配置变化写入审计日志且不记录原始 URL 路径或签名引用；
- `POST /api/v1/projects/{project_id}/quality/webhook/test` 在同一事务中创建测试投递和审计记录，返回 `202`；
- `GET /api/v1/projects/{project_id}/quality/webhook/deliveries` 返回最近投递状态、尝试次数、HTTP 状态码和
  脱敏错误，不保存目标响应正文；
- Alembic `20260817_0012` 新增单项目唯一配置表和独立投递表，包含去重键、状态/时间索引及数据库约束；
- `quality-webhooks` 独立 Compose 服务锁定到期 PENDING 记录，成功状态为 `DELIVERED`；408、425、429、
  5xx 和网络错误按 2–300 秒指数退避，达到上限或确定性 4xx 后标记 `FAILED`；
- 请求采用稳定 JSON 编码，发送 `X-TestOps-Delivery`、`X-TestOps-Event`、`X-TestOps-Timestamp`；配置签名
  后额外发送 `X-TestOps-Signature-256: sha256=<digest>`；
- Vue 质量页可配置启用状态、脱敏 HTTPS 地址、最低等级和签名元数据，可发送测试事件并查看投递历史；
- 平台版本统一提升到 `0.17.0`。

## 安全边界

- 配置入口只接受 HTTPS 443，拒绝用户信息、URL fragment、localhost 和非公网 IP；dispatcher 在连接前再次
  解析 DNS，默认拒绝任意私网或保留地址；
- 原始 Webhook URL 只保存在配置表，所有 API 响应、投递历史和审计记录仅使用 `https://host/***`；
- 签名密钥不通过 API 提交，也不写入数据库。配置只保存名称和 `secret://` 元数据，运行时从
  `TESTOPS_SECRET_<名称>` 读取；缺失时记录通用错误并重试，不回显环境变量或密钥值；
- HTTP 跳转不会自动跟随，响应正文不会读取到业务记录。生产仍必须使用出口代理或域名允许清单约束 DNS
  重绑定和目标域名被接管等应用层无法单独消除的风险。

## 后续状态

仍属于后续范围。
