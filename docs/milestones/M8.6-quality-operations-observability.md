# M8.6 质量运营可观测性与 M8 收尾

## 目标

为 M8.1–M8.5 的质量告警闭环补齐生产值班所需的低基数状态快照与人工操作人可读性，使平台可以回答“评估器
是否落后、投递是否积压、哪些人工动作正在生效”，并以明确完成边界结束 M8 开发。

## 已实现

- 控制面新增独立质量运营快照，统计已启用配置中的到期评估数量、最老评估延迟和当前活跃静默，以及 Webhook
  PENDING/FAILED 数量、最老 PENDING 年龄和人工重放记录总量；
- Prometheus 新增 `testops_quality_alert_evaluation_due_configs`、
  `testops_quality_alert_evaluation_lag_seconds`、`testops_quality_alert_active_silences`、
  `testops_quality_webhook_deliveries{status}`、`testops_quality_webhook_oldest_pending_age_seconds` 和
  `testops_quality_webhook_replay_deliveries`；标签只使用固定状态值，不包含项目、用户、投递或事件 ID；
- 质量快照使用独立的 `testops_quality_operations_snapshot_success`，查询失败不会把 Run/Scheduler 可靠性快照误标为
  失败，反之亦然；数据库不可用时两个快照均明确置为失败；
- Prometheus 规则新增质量快照不可用、evaluator 延迟超过十分钟和 Webhook PENDING 积压超过十分钟三类告警；
- 静默、确认和人工重放响应新增当前操作人显示名；Vue 质量页在静默状态、告警确认说明和重放原因旁直接显示
  操作人，UUID 仍保留用于稳定审计关联；
- 平台版本统一提升到 `0.21.0`。本切片不改变数据库结构，Alembic Head 继续为 `20260817_0015`。

## 指标与隐私边界

- `/metrics` 只做数据库聚合，不触发 evaluator、dispatcher 或外部 HTTP；快照读取失败时保留上次数值并将独立
  success 指标置零，告警接收端可区分“无积压”和“无法查询”；
- FAILED 数量表示保留的历史失败记录，不能直接等同当前故障；值班判断以新失败趋势、PENDING 年龄、测试事件和
  投递链为准。只有 PENDING 年龄进入默认告警，避免已审计的历史失败永久报警；
- 操作人显示名从当前用户目录解析，显示名变更不会改写历史 actor UUID 或审计记录；API 不公开用户名、会话、
  邮箱或其他身份元数据。

## M8 完成边界

M8 已完成以下平台内核闭环：相邻窗口质量检测、可靠 HTTPS Webhook、自动状态机、冷却与静默、人工确认、失败
重放、审计和低基数监控。协议无关 Webhook 是外部通知的稳定扩展边界；企业微信、钉钉等厂商消息格式和凭据模型
属于后续集成能力。当前单项目单活动静默已覆盖维护窗口，重复/周期静默计划属于后续排程能力。这两类扩展不再
作为 M8 未完成项。

## 验证范围

集成测试覆盖质量快照的到期评估、活跃静默、PENDING/FAILED、最老等待和重放计数，以及静默、确认、重放操作人
显示名。本机预验收结果如下：

- 全量 Pytest 93 项、仓库标准入口 68 项通过；Ruff 检查通过，140 个 Python 文件格式一致；
- Schema 导出和不可变基线/Runner 制品摘要检查通过；Vue 严格 TypeScript 检查和 `0.21.0` 生产构建通过；
- Prometheus 告警 YAML 共 11 条，容器内 `promtool` 配置与规则校验通过；Alembic 唯一 Head 为
  `20260817_0015`，完整离线升级 SQL 生成通过，隔离 PostgreSQL 17 完成升级、回滚到 Base、再升级往返；
- 隔离 Compose `0.21.0` 全栈健康，普通冒烟和 Outbox/Worker 中断恢复冒烟通过；成功与预期失败 Run 均校验
  8 个事件，分别校验 1 个和 3 个制品及下载摘要；
- 浏览器闭环确认质量运营页和 evaluator 时间正常；Webhook 测试事件被持久化 dispatcher 在外部 HTTP 前按 SSRF
  规则阻断，FAILED 重放保留原始/子记录、操作人和原因；`/metrics` 暴露全部 M8 指标且质量快照成功值为 `1`；
- 隔离联合备份通过清单校验并恢复到全新的 PostgreSQL/MinIO，用户/项目/Run/制品数量与随机制品摘要一致，
  Alembic 回到 `20260817_0015`，实测 RTO 20.097 秒；
- 本地测试 CA 的 HTTPS 接收器完成 TLS/HMAC 投递：投递一次成功并返回 204，签名、事件类型与投递 ID 均匹配；
  数据库不持久化明文签名密钥，隔离容器日志敏感值扫描命中 0；
- 默认基础镜像已固定到不可变摘要，Bootstrap 空值禁用、1 MiB 入口限制、Nginx 版本隐藏和 `/metrics` 鉴权均经
  隔离环境验证；漏洞扫描受 Docker 登录与外网超时阻断，生产外部接收器、异故障域备份和生产容量仍属于正式门禁。

## 后续方向

下一阶段可根据真实使用优先级选择维度级订阅、投递链详情、周期静默计划、企业 IM 适配器或质量事实物化汇总；
任何新外部适配器仍必须复用现有脱敏、SSRF、签名、持久化投递和审计边界。
