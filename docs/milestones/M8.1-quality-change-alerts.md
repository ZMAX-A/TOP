# M8.1 相邻窗口质量波动告警

## 目标

在 M7.5–M7.7 的质量事实、维度筛选和 Flaky 识别基础上，增加一个可解释的质量变化信号：用当前 UTC
滚动窗口与紧邻的等长上一窗口进行比较，在质量明显下降时直接提示项目成员，同时避免把无样本或不同筛选
范围的数据误报为回归。

## 已实现

- `GET /api/v1/projects/{project_id}/quality/analytics` 增加 `comparison`，同时返回 Run 通过率、Case
  通过率和执行可靠性三个信号的当前值、上一窗口值、百分点变化及独立告警等级；
- 当前窗口继续沿用现有 UTC 统计边界；上一窗口以当前窗口起点为结束边界，并采用相同持续时间。上一窗口
  使用半开区间，确保两个窗口相邻但不重叠；
- 目标、环境和 Released 基线筛选被原样应用到两个窗口，资源归属与目标/环境关系继续由服务端校验；
- 单项等级为 `NO_DATA`、`STABLE`、`WARNING` 或 `CRITICAL`。当前或上一窗口缺少可比指标时返回
  `NO_DATA`；总等级取所有可比指标中的最高等级，全无可比数据时才为 `NO_DATA`；
- 项目质量策略增加警告和严重下降阈值，默认分别为 5 和 10 个百分点。阈值范围为 1–100，且警告阈值
  必须严格小于严重阈值；策略更新继续要求 `project:manage` 权限并写入审计日志；
- Alembic `20260817_0011` 为已有项目补充带默认值和数据库检查约束的策略字段；
- Vue 质量分析页展示上一窗口的明确 UTC 边界、三项变化卡片和总告警状态，项目管理员可在同页调整阈值，
  保存后表单和分析结果同步采用服务端最新值；
- 平台版本统一提升到 `0.16.0`。

## 计算边界

- 通过率仍只使用 `PASSED` 与 `FAILED`；取消、超时和基础设施错误不改变产品质量通过率；
- 执行可靠性分母为有结论 Run、超时 Run 和基础设施错误 Run，取消 Run 不进入该指标；
- 百分点变化为 `当前值 - 上一窗口值`，负值代表下降。下降达到警告阈值为 `WARNING`，达到严重阈值为
  `CRITICAL`，其余可比变化为 `STABLE`；
- 本阶段只计算并展示项目内信号，不发送邮件、IM 或 Webhook，也不把项目 ID 写入 Prometheus 标签。

## 验证与剩余风险

单元测试覆盖稳定、警告、严重和无数据判定；API 集成测试覆盖默认/自定义阈值、非法阈值组合、上一窗口
样本、三项变化和总等级。阶段验收完成以下复验：

- 全量 Pytest 85 项及仓库标准测试入口 66 项通过，Ruff 检查与 124 个 Python 文件格式检查通过；
- Vue 严格 TypeScript 检查和 Vite `0.16.0` 生产构建通过；Schema 导出和版本化制品摘要检查通过；
- Alembic 唯一 Head 为 `20260817_0011`，PostgreSQL 17 完成 `upgrade base -> head -> downgrade base ->
  upgrade head`；
- 保留既有数据卷完成 Compose `0.16.0` 升级，API、Worker、前端与依赖服务健康；普通 Compose 冒烟的
  成功 Run 和预期失败 Run 均通过事件、制品及下载摘要校验；
- 浏览器验证相邻 UTC 窗口、三项变化卡片和 5/10 默认阈值正常渲染；实时把阈值保存为 6/12 后，API
  回读和页面刷新均显示服务端最新值，随后已恢复演示默认值 5/10，页面无应用错误。

当前查询会为上一窗口额外执行 Run 和 Case 聚合。在真实生产数据规模下仍需检查复合维度、大窗口和并发请求
的 PostgreSQL 执行计划；只有证据显示事实表聚合成为瓶颈时，才引入按日物化汇总。外部通知、告警确认/静默
和失败聚类钻取后置到下一阶段。
