# M7.6：目标、环境与基线质量维度

## 目标与完成范围

M7.6 在 M7.5 项目级质量事实之上增加可组合的资源维度，避免不同目标、环境或基线的结果被混合后掩盖
局部回归。本阶段完成：

- `GET /api/v1/projects/{project_id}/quality/analytics` 增加可选 `target_id`、`environment_id` 和
  `baseline_id` 查询参数，可独立使用或组合使用；
- Run 汇总、Case 汇总、UTC 日趋势、SLO 状态、最新完成时间和失败聚类共享同一组筛选条件；
- 响应通过 `filters` 回显服务端实际采用的三个资源 ID，前端不依赖本地推断筛选状态；
- 服务端逐项校验资源属于当前项目；同时提供目标和环境时，环境必须属于该目标；未知或跨项目资源按
  未找到处理，冲突的目标/环境组合按请求校验失败处理；
- Vue 质量分析页加载项目内目标、环境和 Released 基线，支持三维独立/组合筛选、目标与环境联动及一键
  清除；切换窗口和保存 SLO 策略时保留当前质量维度，快速切换时只接受最新分析响应；
- `20260814_0010` 为 `test_runs` 增加项目、维度、状态和完成时间复合索引，分别覆盖目标、环境和基线
  查询入口。

## API 语义

不提供任何维度时，接口保持 M7.5 的项目全量语义。提供维度后，只统计同时满足全部条件且在 UTC 时间
窗口内的终态 Run。合法组合没有数据时返回 `NO_DATA` 和完整的空趋势，不把空数据解释为 `0%` 或 SLO
失败。

环境可以单独筛选；当它与目标同时出现时必须属于该目标。基线维度使用 Run 创建时冻结的
`baseline_id`，不会跟随项目当前最新 Released 基线变化。

## 安全与性能边界

- 维度校验在执行统计 SQL 前完成，避免使用跨项目 UUID 探测其他项目质量数据；
- 前端目录接口和分析接口继续使用项目权限，筛选参数不扩大 `run:read` 能力；
- 复合索引优先缩小项目、维度和终态状态范围；现阶段仍直接读取事实表，不维护重复的聚合结果；
- 失败明细继续执行 M7.5 的 5000 条上限、稳定指纹和消息脱敏规则。
