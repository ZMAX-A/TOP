# M10.3 Central legacy Pytest execution

## Outcome

TOP can dispatch an immutable Run Snapshot to the existing YanJia Excel/Pytest project without
rewriting that project. The browser, Python dependencies, project source and authoritative Excel
workbook live in one package image on the central Worker. End users only select cases and start a
Run in TOP.

The adapter reuses the project's existing A/B account launcher, optional SERIAL group, failure
reruns and JSON aggregation. Each TOP Run receives a writable private copy of the allowlisted
project files. The existing launcher may therefore update that copy of the workbook while the
immutable package workbook remains read-only and unchanged.

## Runtime contract

- Automation package name: `yanjia-web-pytest`
- Runner type: `WEB_PLAYWRIGHT`
- Browser: `chromium`, with the package Playwright context pinned to `zh-CN`. New Runs use the
  environment's headless default and may explicitly select headed mode. Container-isolated headed
  Runs start Chromium through a per-Run Xvfb virtual display. While that Run is active, authorized
  project members can open a read-only noVNC view from the Run detail page. The VNC endpoint stays
  inside the Runner sandbox network: the browser receives a single-use, short-lived ticket from
  the control plane and connects through the same-origin Viewer Gateway. The ticket and VNC
  password are never persisted in Run data or audit details, and the registration is removed when
  execution ends.
- Required secret bindings: `TEST_USERNAME_A`, `TEST_PASSWORD_A`, `TEST_USERNAME_B`,
  `TEST_PASSWORD_B`
- Optional non-secret variables: `STORE_NAME`, `STORE_NAME_A`, `STORE_NAME_B`, `ENV`, `TESTER`,
  `TEST_SERIAL_ACCOUNT_SLOT`
- Selection: enabled Run Snapshot case codes are passed to the existing `run_parallel_tests.py`.
  Its A/B Pytest processes retain the Excel execution-group rules; SERIAL cases still run after
  the parallel batch.
- Outputs: the launcher writes worker JSON, screenshots, Allure data, `summary.json` and its Excel
  result update only inside the private per-Run project copy. TOP then exports the report tree as
  immutable Run artifacts and excludes the copied source tree itself.

The adapter rejects unsupported secrets and variables instead of copying the Worker environment.
It converts the project's JSON result into TOP `CaseResult` records and redacts resolved secret
values before persisting the Pytest log.

## Build the central package image

Run these commands only on the platform build/deployment host. Use a disposable empty export
directory so `.env`, Git metadata, report history, workbook backups and `.venv` are never sent as a
Docker build context.

```powershell
$source = 'C:\path\to\web_test\web'
$export = 'C:\testops-build\yanjia-web-package'
$digest = .\.venv\Scripts\python.exe scripts\package_legacy_pytest.py `
  --source $source --export-to $export
$env:YANJIA_WEB_PACKAGE_CONTEXT = $export
$env:YANJIA_PYTEST_PACKAGE_DIGEST = $digest
$env:YANJIA_PYTEST_IMAGE_TAG = '0.35.2'
$env:YANJIA_TEST_USERNAME_A = '<central test account A>'
$env:YANJIA_TEST_PASSWORD_A = '<central test password A>'
$env:YANJIA_TEST_USERNAME_B = '<central test account B>'
$env:YANJIA_TEST_PASSWORD_B = '<central test password B>'
docker compose -f compose.yaml -f compose.yanjia-pytest.yaml build worker
docker compose -f compose.yaml -f compose.yanjia-pytest.yaml up -d
```

For production, replace Compose environment secrets with the deployment system's secret injection
and register the built image by its immutable OCI digest and verified supply-chain evidence. The
development source digest is still checked against the image label by the container executor.

## Platform configuration

Register an automation package with name `yanjia-web-pytest`, repository
`testops-yanjia-web-pytest`, the exact digest printed above, and pool `yanjia-web`. Environment
configuration supplies `base_url`; secret references bind to the four A/B account variables.
No project checkout, Python, Playwright, Excel file or account password is required on an end
user's computer.

## Acceptance boundary

M10.3 is accepted when adapter unit/integration tests pass, a real project collect-only command can
select an exact case code, the source workbook hash is unchanged, and the merged Compose model
selects the dedicated image, pool and package catalog. A real target login is deliberately outside
this local acceptance because it uses customer credentials and network state.
