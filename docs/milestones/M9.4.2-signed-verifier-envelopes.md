# M9.4.2 验证器服务身份与签名 Envelope

## 目标

M9.4.1 已建立签名、来源证明和 SBOM 的失败关闭策略，但写入入口仍由 System Admin 用户会话代表 CI，无法区分
机器身份、执行密钥轮换或阻止捕获后的报告重放。M9.4.2 将供应链判定写入权限收敛到专用验证器服务凭据，并为每次
请求保存不可变 Envelope 证据。

## Envelope Profile

本阶段采用应用专用的 `testops-supply-chain-envelope-v1` profile，而不是宣称完整实现 RFC 9421。验证器对以下六行
UTF-8 字节执行 HMAC-SHA-256，行间使用单个 LF：

```text
testops-supply-chain-envelope-v1
POST
/api/v1/projects/{project}/targets/{target}/automation-packages/{package}/supply-chain-verifications
{created Unix seconds}
{lowercase UUID nonce}
sha256:{exact request body digest}
```

HTTP 请求通过四个 `X-TestOps-*` Header 传递 credential id、created、nonce 和 `hmac-sha256=<hex>`。方法、目标路径、
签名时间、唯一 nonce 与原始请求体摘要全部被覆盖，因此签名不能替换到另一个包、路径或报告。HMAC 密钥至少 32 字节，
符合 HMAC-SHA-256 输出长度的最低密钥强度边界；生产仍必须启用 TLS。

设计参考 [RFC 2104 HMAC](https://www.rfc-editor.org/info/rfc2104/) 的密钥 MAC 与定期轮换原则，以及
[RFC 9421 HTTP Message Signatures](https://www.rfc-editor.org/rfc/rfc9421.html) 对 key id、创建时间、覆盖请求组件和
nonce 防重放的要求。

## 服务身份、轮换与权限

- `SUPPLY_CHAIN_VERIFIER_HMAC_KEYS` 使用 `<verifier>/<key-id>=<secret>`；`verifier` 必须等于报告内 verifier，并继续
  命中 M9.4.1 的全局允许清单；
- 配置可同时包含最多 16 个 credential。轮换采用先加入新 key、CI 切换、观察成功 Envelope、再移除旧 key 的顺序；
  已移除或未知 key-id 立即认证失败；
- HMAC keyring 只注入 API 服务，不进入数据库、响应、审计详情、前端、Worker、Scheduler、Reaper 或迁移容器；
- POST 供应链判定不再接受 System Admin、Project Admin 或其他用户 Bearer 会话。用户权限只用于读取包、验证记录和
  Envelope 历史；自动化身份在审计日志使用由 credential id 确定生成的稳定 UUID，并在详情内记录非秘密 key-id。

## 防重放与幂等

- 默认 Envelope TTL 为 300 秒、未来时钟偏差上限为 30 秒；格式错误、过期或过度超前都返回 401；
- 新表 `automation_package_supply_chain_envelopes` 追加保存验证记录 ID、服务身份、credential id、nonce、签发/接收
  时间、请求摘要和签名摘要；不保存 HMAC 值或密钥；
- `(credential_id, nonce)` 数据库唯一约束是跨进程并发兜底。同一已消费 nonce 再次提交返回 409；业务或策略校验
  未通过的请求不产生状态变化，也不写入已接受 Envelope；
- 相同报告使用新 nonce 重试仍返回已有不可变验证记录，但会追加新的 Envelope 和幂等审计，不回滚包的较新判定。

## API 与工作台

- `POST .../supply-chain-verifications`：只接受专用签名 Envelope；
- `GET .../supply-chain-verifications`：保持项目读权限与 M9.4.1 兼容；
- `GET .../supply-chain-envelopes`：项目读权限查看认证请求历史；
- 自动化包工作台显示 credential id、签发/接收时间、nonce、请求摘要、签名摘要及其关联验证记录。M9.4.1 旧验证
  记录没有 Envelope，继续显示为明确的历史兼容证据。

## 后续

HMAC 仍要求验证器和 API 共享秘密。下一步可接入工作负载身份和非对称签名/JWS，让控制面只保存公钥或信任根，并增加
credential 使用指标、轮换到期告警和专用验证器健康页；执行侧继续推进 Registry 凭据隔离与每个 Run 独立容器/Pod。
