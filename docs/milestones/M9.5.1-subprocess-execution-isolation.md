# M9.5.1 每 Run 子进程与最小凭据隔离

## 目标

M9.2 已把 Run 绑定到精确不可变自动化包，M9.4 已建立供应链准入，但 Worker 仍在承载控制面连接、对象存储凭据的
Celery 进程内直接执行不受信任的浏览器自动化代码。M9.5.1 将每个 Run 移入独立 Python 子进程，并把子进程可见凭据
收敛到 Run Snapshot 明确声明的测试密钥。

## 执行与信任边界

父 Worker 仍负责数据库/Redis 访问、控制面状态与结果回调、MinIO 上传、取消轮询和超时治理。子进程只接收：

- 不可变 Run Snapshot 的有界 JSON；
- 运行 Python 和 Playwright 所需的非凭据环境变量；
- Snapshot `secret_bindings` 精确匹配的 `TESTOPS_SECRET_<绑定名>`；
- 独立 HOME/TEMP 和该 Run 的工作区根路径。

`DATABASE_URL`、`REDIS_URL`、`CONTROL_PLANE_URL`、`RUNNER_CALLBACK_TOKEN`、MinIO/AWS 凭据以及其他 Run 的
`TESTOPS_SECRET_*` 均不进入子进程。父进程以参数数组和 `shell=False` 启动子进程，标准输出/错误不跨隔离边界，避免
Adapter 异常把已解析密钥带回 Worker 日志。执行期间父进程增量读取子进程写入的 `events.jsonl` 并向控制面补传，保留
实时进度；子进程退出后，父进程验证 Run ID、Result Schema 和隔离证据，再完整重放本地事件、上传制品并提交终态。

## 调度与可观测性

Worker 心跳中的 `execution_isolation` 由受控配置生成，不能从通用能力 JSON 伪造。注册 Worker 必须声明
`SUBPROCESS`、`dedicated_process=true` 和 `credential_scope=RUN_SECRETS_ONLY`，否则 Outbox 保持 Run 为 WAITING 并
返回 `RUNNER_ISOLATION_UNAVAILABLE`。`IN_PROCESS` 仅用于未注册的本地兼容调试。

Run Result 新增 `execution_isolation` 证据，记录执行模式、执行器版本、独立进程、凭据和工作区范围，以及以下尚未实现
的硬隔离事实。运行详情页和 Worker 管理页会直接展示这些边界，不能把子进程等同于容器沙箱。

## 明确不在本阶段的能力

本阶段没有强制只读根文件系统、网络 deny/allowlist、CPU/内存/PID 配额、seccomp/AppArmor 或每 Run 独立容器/Pod。
因此证据固定为 `read_only_root_filesystem=false`、`network_policy=WORKER_DEFAULT` 和
`resource_limits_enforced=false`。M9.5.2 应以容器或 Kubernetes 执行器补齐这些能力，并由控制面按项目策略选择和验证。

## 配置、版本与验证

- `RUNNER_EXECUTION_MODE=SUBPROCESS` 为默认生产模式；
- `RUNNER_EXECUTOR_POLL_SECONDS` 控制取消轮询，范围 0.1–10 秒；
- `RUNNER_EXECUTOR_TIMEOUT_SECONDS` 控制本地执行器上限，范围 60–86400 秒；
- 平台版本提升到 `0.27.0`，本阶段不改变数据库结构，Alembic Head 仍为 `20260820_0018`。

单元测试覆盖精确凭据注入、控制面/存储凭据排除、隔离证据不夸大、子进程 Result 持久化、配置防伪与边界；Worker
测试覆盖父进程不构造 Adapter，控制面集成测试覆盖不满足隔离能力时失败关闭。Compose Smoke 还会逐 Run 校验
`SUBPROCESS`、执行器版本、独立进程、最小凭据范围和未实现的硬隔离字段，防止镜像/环境版本漂移被误报为通过。

本机预验收结果：全量 Pytest `113 passed`、仓库标准入口 `87 tests OK`；Ruff、Schema、不可变制品、发布/部署契约、
Vue 严格类型检查及 `0.27.0` 生产构建通过。独立 `testops-m951-verify` 栈使用固定基础镜像、独立端口和独立卷，所有
服务健康；真实 PostgreSQL 17 完成 `0018 -> 0017 -> 0018` 往返并回到唯一 Head。普通 Smoke 与 Outbox/Worker
中断恢复 Smoke 均通过：每轮成功/预期失败 Run 各有 8 个事件和 1/3 个制品，下载摘要全部一致，最终 Result 的
`executor_version` 为 `0.27.0`。这些证据解除本机 Docker、真实数据库和 Compose 验证限制，但不改变 M9.5.1 的
功能边界；每 Run 容器/Pod 硬隔离仍属于 M9.5.2。

## 后续

M9.5.2 引入真正的每 Run 容器/Pod、只读根文件系统、临时可写层、资源配额和网络策略；随后补充工作负载身份、短期
Registry/对象存储凭据、沙箱运行指标和异常容器清理闭环。
