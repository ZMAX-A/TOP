# M7.5：项目质量分析与 SLO

## 目标与完成范围

M7.5 在不可变 Run Result 和逐用例结果之上增加项目质量闭环。本阶段完成：

- 项目级质量策略：目标 Run 通过率 `1%`～`100%`，默认滚动窗口 `7`～`90` 天；
- `GET /api/v1/projects/{project_id}/quality/analytics` 按 UTC 日历日返回 Run/Case 汇总、
  日趋势、SLO 状态和失败聚类；调用方可在 `1`～`90` 天内临时覆盖查询窗口而不修改项目策略；
- 质量通过率只使用 `PASSED/FAILED` 的有结论 Run，`TIMED_OUT/INFRA_ERROR` 单独进入执行
  可靠性，`CANCELED` 只保留数量，不污染质量或可靠性分母；
- Case 维度分别展示通过、失败、跳过、取消、超时和基础设施错误；
- 失败聚类按类别和归一化消息生成稳定 SHA-256 指纹，URL、UUID、长十六进制、数字和常见
  密钥字段在返回前归一化或脱敏；聚类最多扫描当前窗口最近 `5000` 条异常 Case，并显式返回截断标志；
- Vue 管理端增加独立质量分析页面，展示 SLO、Run/Case 通过率、执行可靠性、UTC 日趋势、
  失败聚类和可管理的项目质量策略；
- 项目质量策略变更写入 `project.quality_policy_updated` 审计记录。

## 数据与口径

Alembic `20260813_0009` 在 `projects` 增加：

- `quality_slo_target_percent`，默认 `95`；
- `quality_slo_window_days`，默认 `30`。

当前阶段直接基于索引化的 `test_runs(project_id, status, created_at)`、`finished_at` 和
`run_cases(run_id)` 读取事实数据，不写物化统计结果。查询窗口定义为从 UTC 当天向前包含当天的
N 个完整日历日；正在运行的任务不进入质量结论。

## 安全与边界

- 分析接口使用 `run:read` 项目权限，策略更新使用 `project:manage`；
- API 不返回未归一化的聚类消息，也不返回样例密钥值；
- SLO 策略更新经项目行锁串行化，并保留 before/after 审计证据；
- `NO_DATA` 与 `0%` 明确区分，避免没有有结论 Run 时误报 SLO 失败。

## 后续

目标/环境/基线维度筛选已在 M7.6 实现，Flaky Case 识别已在 M7.7 实现。下一阶段优先增加相邻 UTC 窗口
质量波动告警和失败聚类钻取。当单项目窗口内异常 Case 超过当前读取上限时，再基于真实查询证据引入按日
物化汇总与增量聚类表；容量预测和跨项目质量组合视图继续后置。
