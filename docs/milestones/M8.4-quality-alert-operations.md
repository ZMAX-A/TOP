# M8.4 质量告警人工确认与限时静默

## 目标

在 M8.3 自动状态机之上增加最小人工处置闭环：项目成员仍能看到持续更新的质量事实，项目管理员可以明确记录
谁已确认当前问题，并在发布维护等已知窗口内暂停外部通知，同时保证静默不会吞掉之后仍需发送的升级或恢复。

## 已实现

- `PUT/DELETE /api/v1/projects/{project_id}/quality/webhook/states/{metric}/acknowledgement` 为
  WARNING/CRITICAL 指标设置或取消人工确认，确认包含操作人、UTC 时间和最多 500 字的说明；
- `PUT/DELETE /api/v1/projects/{project_id}/quality/webhook/silence` 设置或解除项目级静默；Webhook 必须已启用，
  截止时间必须在未来且单次不超过 30 天；
- evaluator 在静默期继续计算并持久化三个质量指标，但不创建投递，也不推进 `active_notification_status` 和通知
  序号；解除或到期后的下一次评估会按最新事实补发仍成立的触发、升级、降级或恢复事件；
- 任一指标状态发生变化时自动清除旧确认，避免已恢复或已升级的问题继续显示过期处置结论；Webhook 启停或最低
  通知等级变化也会清理确认和通知冷却状态；
- 配置与状态 API 向有项目读取权限的成员公开静默和确认状态，但设置、解除、确认和取消确认均要求
  `project:manage`；所有人工操作写入独立审计动作；
- Vue 质量分析页显示静默截止时间、原因和指标确认说明，项目管理员可在同页完成处置；
- Alembic `20260817_0014` 增加静默与确认字段及全空/全非空数据库约束，平台版本提升到 `0.19.0`。

## 状态与事务边界

- 人工确认只表达“有人处理”，不改变质量等级、外部通知等级或 evaluator 调度；同一状态可更新确认说明，历史由
  审计日志保留；
- 静默只抑制自动质量事件，不阻止管理员发送 Webhook 测试事件，也不暂停 Run、Scheduler、Reaper 或质量计算；
- 静默期间保留最后一次真实对外通知状态。这样 WARNING 在静默期升级为 CRITICAL、或活跃告警在静默期恢复时，
  解除静默后仍能分别生成 `escalated` 或 `recovered`，不会把未发送事件误认为已发送；
- 解除静默会把配置重新安排为立即到期评估；静默截止时间早于常规下次评估时，也会把持久化调度点提前到静默
  截止时间。多实例仍通过配置行锁和投递唯一键保持幂等。
