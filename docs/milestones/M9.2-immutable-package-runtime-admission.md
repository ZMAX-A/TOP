# M9.2 不可变自动化包运行时准入

## 目标

把 M9.1 冻结进 Run Snapshot 的 Runner 类型、OCI 仓库和摘要真正接入执行调度。平台必须在派发和执行两个位置
确认 Worker 承载精确的不可变包，不能因为目标类型和浏览器匹配就让任意内置 Adapter 接收任务。

## 已实现

- 新增共享 `AutomationPackageRuntimeRef`，由控制面心跳、Worker 本地目录和 Run Snapshot 复用同一套
  `runner_type + image_repository + digest` 校验；仓库名拒绝协议、内联摘要、空白和可变标签；
- Worker 从独立的 `RUNNER_PACKAGE_CATALOG` JSON 数组读取预装包，最多 50 项，拒绝非法结构和重复引用；注册到
  Runner Pool 的 Worker 没有目录时拒绝启动，目录不能混入普通 `RUNNER_CAPABILITIES`；
- Worker 心跳将目录写入 `capabilities.automation_packages`，系统管理端展示每个 Worker 承载的仓库、摘要前缀和
  数量；历史 Worker 记录缺少该字段时按空目录处理；
- Outbox 先匹配目标类型和浏览器，再按精确不可变引用筛选 Worker。前者失败保留
  `RUNNER_CAPABILITY_MISMATCH`，后者明确记录 `AUTOMATION_PACKAGE_UNAVAILABLE`，两者都保持 Run 为 WAITING，
  不占用不兼容 Worker 的槽位；
- Celery 任务在 PREPARING 后、创建 Adapter 前再次用本地目录校验 Snapshot。即使心跳记录过期或消息被错误路由，
  也不会进入业务 Adapter；结果以 `INFRA_ERROR/AUTOMATION_PACKAGE_UNAVAILABLE` 上报；
- Compose 默认目录只声明当前镜像内置的 Web Runner 摘要，Smoke 包使用同一个确定性源码摘要，不再使用与运行时
  无关的名称/版本伪摘要。

## 信任与隔离边界

M9.2 采用“预装运行时”模式：目录只是 Worker 镜像已经承载内容的声明，不会触发网络下载、动态 import、Shell
命令或 Docker Socket 调用。这样在尚未具备 Registry 凭据隔离、签名/证明校验、只读根文件系统和独立执行沙箱
前，不会把控制面输入升级成远程代码执行能力。

本地 Compose 以 Web Runner 源码的确定性 SHA-256 作为包内容摘要，便于当前单仓开发与回归。生产构建应把最终
OCI Manifest Digest 作为自动化包和 `RUNNER_PACKAGE_CATALOG` 的共同事实来源，并通过部署流水线注入，不能手工
填写标签摘要或把 `latest` 解析结果长期缓存为事实。

## 自动化脚本更新操作

1. 在 CI 中构建新 Worker/Runner 镜像，完成扫描和测试后取得最终 OCI Manifest Digest；
2. 创建新的 `DRAFT` 自动化包版本，写入不带标签的仓库名和该摘要，不覆盖已有版本；
3. 先部署一组同时声明旧、新摘要的 Worker，等待心跳在系统管理中心显示新引用；此时旧 Run 仍有可用容量；
4. 对新草稿创建 Released 基线全量验证 Run。调度若显示 `AUTOMATION_PACKAGE_UNAVAILABLE`，先修复 Worker 部署，
   不要修改 Run Snapshot 或把包直接激活；
5. 验证通过后激活新包，逐步把普通执行和定时回归切换到新版本，再弃用旧包；
6. 确认没有需要旧包的新任务后排空旧 Worker，并从目录移除旧摘要。需要历史重跑时应保留对应 Worker 容量；
7. 包存在安全或完整性风险时直接吊销。吊销会阻止新执行和历史重跑，但已经在途的 Run 仍按既有 M9.1 边界处理。

## 兼容与版本

- 平台版本提升到 `0.23.0`，本切片复用 Runner Worker 的 JSON 能力列，不改变数据库结构；Alembic Head 继续为
  `20260820_0016`；
- API 接受不带 `automation_packages` 的旧心跳并保存为空目录，但这种 Worker 不再满足任何新 Run 的包准入；
- 已经产生的 Run Snapshot 和 Result 不被改写；本地结果恢复与终态任务忽略逻辑在目录校验之前运行，避免因移除
  旧包而破坏已完成结果的幂等补传。

## 验证范围

- 全量 Pytest `100 passed`，仓库依赖精简入口 `75 tests OK`；Ruff 检查通过，145 个 Python 文件格式一致；
- 目录测试覆盖精确解析、摘要不匹配、可变/重复/超限配置、注册 Worker 空目录拒绝和心跳能力合并；Worker 测试
  确认不可用包不会实例化 Adapter；
- 控制面集成测试区分浏览器能力不匹配和包不可用，并验证只有精确摘要 Worker 才会取得槽位与任务；
- Schema、不可变基线和 Runner Job 摘要检查通过；Vue 严格 TypeScript 检查和 `0.23.0` 生产构建通过；
- 唯一命名、独立端口的隔离 Compose `0.23.0` 全栈健康。成功 Run 为 PASSED、8 个事件和 1 个制品；预期失败
  Run 为 FAILED、8 个事件和 3 个制品，4 次短时下载摘要全部一致；隔离项目及其容器、网络和卷已删除；
- 本切片不改变数据库结构；Alembic Head 和 M9.1 PostgreSQL 往返证据继续为 `20260820_0016`。

## 完成边界与后续

M9.2 完成预装运行时的精确声明、调度和执行前二次校验。远端 Registry 拉取、认证、OCI 签名和 provenance、每个
Run 独立容器/Pod、资源限制及网络策略尚未实现；这些能力必须以隔离执行器为前提，不能通过给当前 Worker 挂载
宿主 Docker Socket 来绕过。
