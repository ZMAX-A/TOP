# M9.1 自动化包生命周期控制面

## 目标

把自动化包从“由管理员直接登记为可执行资源”升级为可验证、可激活、可弃用和可吊销的治理对象，并把包的
Runner 类型、OCI 仓库与不可变摘要冻结进 Run Snapshot。普通 Run 和定时回归只能选择已激活包，避免未经
验证或已退出使用的脚本进入新的业务执行。

## 生命周期

```text
DRAFT --全量验证 Run 通过--> ACTIVE --停止新执行--> DEPRECATED
  |                              |                      |
  +------------------------------+----------------------+--> REVOKED
```

- `DRAFT`：项目管理员创建候选包，可创建全量验证 Run，不能创建普通 Run 或定时回归；
- `ACTIVE`：验证 Run 必须使用同一项目、目标和候选包，基线为 `RELEASED`，覆盖全部启用用例，最终状态为
  `PASSED` 且有结果摘要；激活操作保存验证 Run、操作人和时间；
- `DEPRECATED`：不再允许新的普通 Run 或计划引用，但保留历史 Run 的可追溯性和重跑能力；仍被活动定时回归
  引用时必须先暂停或修改计划，不能直接弃用；
- `REVOKED`：立即禁止新的普通 Run、计划和历史重跑，适用于已确认存在安全、完整性或合规问题的包；
- 重复提交相同的激活、弃用或吊销请求是幂等的；状态原因和所有变更均写入审计事件。

## 数据与 API

- `automation_packages` 新增 `runner_type`、`image_repository`、`supersedes_id`、`validated_run_id`、
  `activated_by`、`activated_at` 和 `status_reason`；状态数据库约束扩展为 `DRAFT`、`ACTIVE`、
  `DEPRECATED`、`REVOKED`；
- `runner_type` 当前只允许 `WEB_PLAYWRIGHT`。`image_repository` 只接收不含协议、摘要、空白和可变标签的
  OCI 仓库名；镜像内容继续由 `digest` 的 `sha256:` 摘要唯一确定；
- 项目管理员可创建草稿、读取详情、创建验证 Run、激活、弃用和吊销；历史直接创建 `ACTIVE` 包的接口仅保留给
  System Admin，供引导和兼容流程使用；
- 草稿创建可声明 `supersedes_id`，服务端要求被替代包属于同一目标、同名且未吊销，包版本仍由
  `(target_id, name, version)` 唯一约束保护；
- Run Snapshot 的 `automation_package` 固定记录名称、版本、摘要、Runner 类型和 OCI 仓库。Worker 不根据
  数据库当前状态静默替换版本。

## Run 与计划边界

- 普通 Run、变更验证 Run、候选基线全量回归和定时回归创建时统一要求自动化包为 `ACTIVE`；
- 自动化包验证 Run 是唯一允许使用 `DRAFT` 的入口，并强制使用所选 Released 基线的全部启用用例；
- 弃用不改写历史 Snapshot，来源 Run 使用弃用包时仍可重跑；吊销会在重跑入口再次校验并拒绝；
- 已经创建的 Run 保持不可变。本切片不终止已经在途的 Run，也不让 Worker 在执行途中重新查询包状态。

## 兼容与迁移

- 平台版本提升到 `0.22.0`，Alembic Head 为 `20260820_0016`；
- 新增的 Runner 类型和 OCI 仓库列保留数据库默认值，支持迁移期间旧版 API 尚未显式写入新字段的滚动兼容；
- 现有自动化包迁移后保持 `ACTIVE`，原有包注册 API 的请求体继续兼容；权限收紧为 System Admin，正常项目流程
  应改用草稿生命周期；
- 契约模型为旧 Snapshot 提供相同默认值，历史固定 Job 仍能解析；新建 Snapshot 会显式序列化两个字段。

## 验证范围

集成测试覆盖草稿仓库校验、重复版本冲突、DRAFT 普通执行拦截、全量验证 Run 幂等、激活前置条件、ACTIVE
普通执行、活动计划弃用保护、弃用后新执行拦截、吊销后重跑拦截、生命周期审计和项目管理员权限边界。还验证
Schema/不可变制品、Runner 契约、前端严格类型检查、迁移元数据与离线升级 SQL。本机预验收结果如下：

- 全量 Pytest `94 passed`，仓库依赖精简入口 `69 tests OK`；Ruff 检查通过，142 个 Python 文件格式一致；
- Schema 导出检查和不可变基线/Runner Job 摘要检查通过，Runner 源码摘要更新为
  `sha256:e040482d91882b9be417b94cd0c404c072b7988bd61a04bb6d82da1f0b68f5e7`；
- Vue 严格 TypeScript 检查和 `0.22.0` 生产构建通过；
- Alembic 唯一 Head 为 `20260820_0016`，完整离线升级 SQL 生成通过；隔离 PostgreSQL 17 完成首次升级、回退到
  `20260817_0015` 后再升级，以及回退到 Base 后再升级的往返，数据库默认值、检查约束和外键均存在；
- 本切片未执行隔离 Compose 全栈冒烟，动态 OCI 执行也不在 M9.1 完成范围内。

## 完成边界与后续

M9.1 完成生命周期控制面和执行准入。本切片没有实现远端 OCI Registry 拉取、签名/证明校验、动态 Runner
镜像分发或生命周期管理页面；前端只补齐 API 客户端并在现有 Run/计划选择器中限制 `ACTIVE` 包。后续 M9
切片应先实现受控镜像解析与执行，再补管理界面、供应链证明、回滚和分阶段发布策略。
