# M10.4 用户级 Run 结果邮件通知

## 目标

允许每位登录用户维护最多 5 个收件邮箱和结果范围，并在本人发起的 Run 进入终态后收到邮件。邮件投递不得
阻塞 Run 结果落库，也不得把 SMTP 凭据交给普通用户或写入数据库、API 响应和日志。

## 用户流程

1. 从左侧导航栏进入“邮件通知设置”；
2. 填写 1 至 5 个收件邮箱，勾选本次实际接收通知的地址，再选择通过、失败、基础设施异常、超时或取消等结果；
3. 平台 SMTP 可用时启用通知并保存；
4. 可发送一封测试邮件；此后仅当前账号发起的 Run 会按选择的终态通知。

关闭通知代表完全停止发送；取消某个邮箱的“发送”勾选只会暂停向该地址投递，邮箱仍保留在配置中，随时可以
重新选择。开启后仍然只通知当前账号发起的 Run，不会订阅其他账号的结果。用户停用通知、更换邮箱列表或
调整已选择邮箱时，尚未发送的旧投递会标记为 `CANCELED`，避免继续向旧地址发送。

## 可靠性设计

- `run_email_preferences` 分别保存已配置邮箱与已选择邮箱，同时保存启用状态和订阅终态；旧数据升级后默认全部选中；
- `run_email_deliveries` 保存去重键、脱敏目标、最小 Run 摘要、状态、尝试次数和下次可用时间；
- Runner 回调记录终态结果时，在同一事务中为每个收件邮箱写入独立投递；排队取消的 Run 也使用相同入口；
- 独立 `run-emails` Compose 服务通过 SMTP 异步发送，按 2–300 秒指数退避并执行有界重试；
- 邮件提供纯文本与 HTML 两种正文，包含项目、Run、分项统计、耗时、基线、自动化包和详情链接；
- API、审计和 dispatcher 日志只使用脱敏邮箱，不返回或打印 SMTP 密码。

## 平台配置

SMTP 由平台管理员在环境中统一配置：

```dotenv
PUBLIC_BASE_URL=https://testops.example.com
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=testops@example.com
SMTP_PASSWORD=<app-password-or-secret>
SMTP_FROM_ADDRESS=testops@example.com
SMTP_FROM_NAME=TestOps Platform
SMTP_STARTTLS=true
SMTP_USE_SSL=false
```

`SMTP_STARTTLS` 与 `SMTP_USE_SSL` 不能同时启用。若邮件服务器使用 465 端口的隐式 TLS，应设置
`SMTP_USE_SSL=true`、`SMTP_STARTTLS=false`。只有 SMTP 主机和发件地址完整时，用户界面才允许启用通知或发送
测试邮件。

## 边界

- 当前版本通知 Run 创建者，不向整个项目成员群发；
- 邮件正文不附带截图、日志、测试账号、令牌或其他敏感制品，只提供受登录保护的 Run 详情链接；
- 邮箱属于用户数据，仅当前用户可通过个人接口读写；系统审计只记录是否配置和订阅状态；
- 每个账号最多保存 5 个唯一邮箱；每个地址独立发送与重试，一个地址失败不影响其他地址；
- 本功能不替代现有项目质量 Webhook，两者使用独立队列和投递进程。
