# M9.6.2 验证器公钥生命周期

## 目标

M9.6.1 允许同一工作负载身份同时绑定旧、新 Ed25519 公钥，但轮换只能通过增删配置完成，无法提前声明启用时间、强制
到期或在泄漏事件中立即吊销。M9.6.2 为每个 verifier key 增加明确的时间边界，让灰度轮换和紧急拒绝都由控制面失败
关闭地执行，同时保持历史 Envelope 与旧三字段配置可读。

## 配置契约

`SUPPLY_CHAIN_VERIFIER_ED25519_KEYS` 每项仍必须包含 `credential_id`、`workload_identity`、`public_key`，并可增加：

- `not_before`：key 启用时间，包含该时刻；
- `not_after`：key 到期时间，不包含该时刻；
- `revoked_at`：计划或紧急吊销时间，不包含该时刻。

时间只接受 `YYYY-MM-DDTHH:MM:SSZ` 形式的整秒 UTC。带偏移量、小数秒、无时区、无效日期及
`not_before >= not_after` 在 API 启动时被拒绝。字段省略时保持 M9.6.1 无时间边界的兼容行为；生产配置必须显式设置
启用和到期时间。

## 验签语义

控制面先按 v2 协议验证 Ed25519 签名，再以同一个 key 检查 Envelope `created` 和服务端 `utc_now()`。两个时间点都必须
不早于 `not_before`、早于 `not_after`，并早于 `revoked_at`。双时间检查阻止在 key 启用前预签未来 Envelope，也阻止在
到期或吊销后继续提交先前签发但尚处于 Envelope TTL 内的请求。

未知 key、错误签名、未启用、已到期和已吊销统一返回 401，不暴露 credential 是否存在或具体生命周期状态。生命周期
配置只进入 API，私钥、签名 Header 与公钥原文仍不进入数据库、Worker 或前端；已接受的 Envelope 继续用 credential、
工作负载身份和公钥指纹审计，因此本阶段不需要数据库迁移。

## 轮换与紧急吊销

正常轮换先配置带未来 `not_before` 的新 key 和带观察期 `not_after` 的旧 key，重启所有 API，待新 key 启用后切换验证器
私钥与 key-id；观察新指纹后验证旧 key 到期拒绝，最后移除旧 key。紧急事件为受影响 key 设置不晚于当前 UTC 的
`revoked_at` 并重启全部 API，随后用唯一 nonce 证明旧 key 返回 401。配置只在进程启动时读取，因此变更与重启必须作为
同一运维操作并留下时间、配置摘要、API 实例和 Envelope 审计证据。

## 验证边界

单元测试覆盖旧配置兼容、规范 UTC 解析、无效/倒置窗口、启用边界、到期边界和吊销边界。M9.6.1 已有的错误 key、身份
替换、TTL、nonce 重放、业务幂等和双 key 历史审计继续回归。

本阶段没有完成真实 CI 私钥保护、生产 TLS、真实双 key 流量切换与旧 key 拒绝观测，也不等同于 OIDC/SPIFFE 联邦
验证；这些项目继续作为发布门禁。
