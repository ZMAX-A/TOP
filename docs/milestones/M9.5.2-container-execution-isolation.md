# M9.5.2 每 Run 容器硬隔离

## 目标

M9.5.1 已将不受信任自动化代码从 Celery 主进程移入独立子进程，并把凭据收敛为 Snapshot 声明的测试密钥；但子进程
仍继承 Worker 的文件系统、网络和宿主资源边界。M9.5.2 新增 Docker 容器执行器，使每个 Run 具有独立容器、只读根
文件系统、专用工作区和输入卷、受控网络以及 CPU、内存、PID 限额。

## 执行与输入边界

父 Worker 仍是受信任执行控制器，负责控制面回调、Redis、对象存储、取消/超时和 Docker 生命周期。Run 容器不会挂载
Docker Socket，也不会接收数据库、Redis、控制面或对象存储凭据。其输入仅包含：

- 不可变 Run Snapshot；
- Snapshot `secret_bindings` 精确匹配的 `TESTOPS_SECRET_*`；
- 执行器版本、实际本地镜像 ID 和资源策略证据。

Snapshot 不包含解析后的密钥值。父进程先把 Snapshot 写入一次性受管输入卷，再以只读方式挂载到 Run 容器；Run 输出
写入另一个一次性工作区卷。容器结束后，父进程用有界 Tar 导入器拒绝绝对路径、目录穿越、链接、设备文件、超量文件
和超量归档，再校验 Run ID、Result Schema 和隔离证据。无论成功、失败、取消或超时，专属容器与两个卷都被回收；同一
Run 重试只会回收标签同时匹配 `io.testops.managed=true` 和 Run ID 的陈旧资源，名称冲突时失败关闭。

## 硬隔离策略

默认 Compose 容器模式强制：

- `read_only=true`、非 root `pwuser`，镜像标签固定 UID/GID `1001/1001`；
- `cap_drop=ALL`、`no-new-privileges`，Run 容器无 Docker Socket；
- `/tmp`、`/home/pwuser` 为有界 `noexec,nosuid,nodev` tmpfs；
- 工作区卷可写、Snapshot 输入卷只读；
- `ALLOWLIST` 内部网络只连接确定的测试目标，或按策略使用 `DENY_ALL`；
- 默认 1 GiB 内存、1000 millicores、256 PID、512 MiB `/dev/shm`。

容器启动后，父 Worker 从 Docker Engine 回读实际镜像 ID、用户、只读根、特权位、网络、内存、NanoCPU、PID、共享内存、
Capability、SecurityOpt、tmpfs 和挂载读写属性。任何值与声明不一致都会在执行开始阶段失败关闭，Result 不会声称未经
确认的硬隔离。

## 镜像与调度准入

容器执行器只使用本机已存在的 `RUNNER_CONTAINER_IMAGE`，不在 Run 路径隐式拉取。镜像必须同时满足：

- Docker 返回不可变 `sha256:` 本地镜像 ID；
- `io.testops.package.digest` 等于 Run Snapshot 已准入的自动化包摘要；
- `io.testops.runtime.uid/gid` 等于固定非 root 身份。

Worker 心跳的容器能力由受控配置生成，包含精确资源限制且不能通过通用能力 JSON 覆盖。控制面拒绝字段不完整或自相
矛盾的 `CONTAINER` 心跳；同一 Pool 同时存在子进程与容器 Worker 时，优先选择容器 Worker，同时保留 M9.5.1 的滚动
升级兼容性。

## 配置与版本

- `RUNNER_EXECUTION_MODE=CONTAINER`；
- `RUNNER_CONTAINER_IMAGE=testops-worker:0.28.0`；
- `RUNNER_CONTAINER_NETWORK_POLICY=ALLOWLIST|DENY_ALL`；
- `RUNNER_CONTAINER_NETWORK` 在 ALLOWLIST 模式必填；
- `RUNNER_CONTAINER_MEMORY_MIB`、`RUNNER_CONTAINER_CPU_MILLIS`、
  `RUNNER_CONTAINER_PIDS_LIMIT`、`RUNNER_CONTAINER_SHM_MIB` 均有界；
- 平台版本为 `0.28.0`，本阶段不改变数据库结构，Alembic Head 仍为 `20260820_0018`。

Compose 的 Worker 挂载 Docker Socket 只用于本地单节点执行控制器。生产环境应把这一高权限边界放入独立受控节点，限制
谁能配置 Worker，并优先迁移到 mTLS 远程执行服务或 Kubernetes API 与专用 ServiceAccount；不能把 Docker Socket
暴露给 Run 容器。

## 当前验证证据

单元测试覆盖最小凭据环境、完整能力门禁、创建参数、Snapshot 一次性卷、安全归档导入、镜像标签匹配、结果证据、资源
清理和 Worker 路由。独立 `testops-m952-verify` Compose 栈已用 Docker Engine 29.7.2 在启动后 Engine 参数回读自校验启用
的情况下完成普通及 Outbox/Worker 中断恢复 Smoke。两组成功 Run 均为 PASSED/8 事件/1 制品，预期失败 Run 均为
FAILED/8 事件/3 制品，下载摘要一致；Result 记录 `CONTAINER`、`0.28.0`、只读根、ALLOWLIST、1 GiB、
1000 millicores、256 PID 和不可变本地镜像 ID `sha256:8d2357bc5a1ffe3cfefc9bc18ac9e5d07dcf5b6988cefe032fa19ef05731dece`。
恢复烟测后独立栈全部服务健康，错误日志扫描无命中，标签为 `io.testops.managed=true` 的 Run 容器和卷均为零残留。
