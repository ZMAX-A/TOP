# M10.2 — 可配置 AI 模型接入

## 目标

在不改变 TOP AI 助手证据构建、只读边界、结构化输出校验和对话持久化的前提下，允许系统管理员接入多个 OpenAI-compatible 模型，并由用户在 AI 助手中选择本次对话使用的模型。

## 行为

- 现有 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 环境变量模型继续保留；没有自定义默认模型时，它仍是平台默认模型。
- 系统管理员可在“系统管理 > AI 模型”新增、编辑、启停、删除、测试连接及切换默认模型。
- AI 助手按请求携带模型配置标识；不携带时使用平台默认模型。Run 详情中的失败分析同样使用平台默认模型。
- 删除或停用自定义默认模型后，平台自动回退到环境变量模型；历史对话及其中记录的模型名称不受影响。

## 安全边界

- 自定义 API Key 使用服务端 wrapping key 加密后写入数据库，任何响应和审计详情都不返回密钥原文。
- 推荐单独配置不少于 32 字节的 `AI_PROVIDER_ENCRYPTION_KEY`；为兼容当前部署，未设置时可回退使用 `AI_API_KEY` 派生 wrapping key。
- Base URL 禁止用户名、密码、查询参数和 fragment。非本机明文 HTTP 仍受现有 `AI_ALLOW_INSECURE_HTTP` 开关约束。
- 连通性探测只发送固定字符串，不回显模型响应正文。
- 模型配置变更仅限系统管理员，并写入不可变审计日志。
