# M0.5：首个不可变用例基线

## 结果

旧项目 `../web/test_cases/test_case.xlsx` 已作为只读输入迁移成
`baselines/yanjia-ai-web/case-v1.0.0`。

- 基线 UUID：`e9616299-f3e2-51a2-bb3c-4ea853ad51be`；
- 用例总数：92；
- 启用：89；禁用：3；
- 迁移错误：0；
- 可追踪规范化：25 项；
- 旧执行器不会消费的输入槽：8 项，已在审计中以内容哈希记录，未泄露值；
- 基线 SHA-256：见 `manifest.json`，不在文档中重复维护。

## 迁移规则

1. Case UUID 由项目键和用例编号通过 UUIDv5 确定，跨基线版本稳定。
2. Baseline UUID 由项目键和基线版本通过 UUIDv5 确定。
3. 输入槽保持旧执行器的 `|` 顺序；非空值去除首尾空白，纯空白输入原样保留。
4. 旧执行器隐式使用的最后一个非空定位器被显式写入断言。
5. 数值型 Excel 输入转为十进制字符串，避免手机号等文本数据改变语义。
6. `p1` 规范化为 `P1`，中文优先级“中”规范化为 `P2`。
7. `实际结果` 属于历史运行态数据，不进入定义基线。

## 不可变性

迁移器允许对已发布目录做同内容幂等验证；如果任一文件内容不同，会拒绝覆盖，
必须发布新的 `case-vX.Y.Z`。Run Snapshot 通过基线 UUID、版本、用例数和 SHA-256
共同引用该基线。

## 验证

- Pydantic 可完整加载 92 条 Case Definition；
- 清单中的基线哈希与文件内容一致；
- 源 Excel 在当前开发机存在时，测试会执行逐字节再生成校验；
- 空格输入、数值输入、日期范围、禁用用例和 `retry_report` 均有回归测试。
