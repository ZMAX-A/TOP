# M9.9 验证器密钥环配置摘要与部署预检

## 目标

M9.8 已能监控单个 API 进程当前加载的密钥就绪状态，但固定低基数指标不能表达多副本之间的具体 keyring 配置差异。
M9.9 增加稳定、非秘密的配置摘要和失败关闭的部署前 CLI，使滚动发布可以逐实例证明公钥环、生命周期和轮换策略一致，
同时保持 Prometheus 标签边界不变。

## 稳定配置摘要

就绪快照和 System Admin 的 `GET /api/v1/admin/supply-chain/verifier-keys` 响应新增 `configuration_digest`。摘要输入使用
带固定 `testops-supply-chain-keyring-v1` profile 的确定性 JSON 规范化，并覆盖：

- 到期预警天数与历史 HMAC 兼容开关；
- 排序后的 HMAC credential id，但不包含 HMAC secret；
- 排序后的 Ed25519 credential、verifier、工作负载身份、公钥 SHA-256 指纹和规范 UTC 生命周期时间。

摘要不包含抓取时间、当前生命周期分类或聚合计数，因此相同配置在不同时间和不同数组顺序下保持一致；公钥、生命周期、
身份或策略变化都会产生新摘要。它证明的是摘要输入的一致性，不证明 HMAC secret 相同，也不替代镜像摘要、环境注入来源、
UTC 时钟和真实验签流量检查。

管理员页面展示摘要，供人工逐实例比对。摘要不会进入 Prometheus 标签或新建带摘要值的时序，M9.8 的固定枚举低基数约束
保持不变。

## 失败关闭预检

`scripts/check_supply_chain_key_readiness.py` 直接从最终进程环境加载配置并复用同一就绪计算：

- `READY` 返回 0；
- `WARNING` 默认返回 2；
- `BLOCKED` 返回 3；
- 配置解析或校验失败返回 4，并只打印通用错误，不回显可能含 secret 的异常文本。

标准 JSON 输出只保留配置摘要、快照时间、聚合计数、重叠/HMAC 状态和稳定告警代码，不包含逐 key credential、工作负载
身份或指纹。`--allow-warning` 只用于有审批和到期时间的受控迁移窗口；生产门禁默认不得启用。

## 多副本发布流程

滚动发布必须绕过负载均衡入口，对每个 API Pod/实例运行预检或直接读取其管理员接口，记录实例、镜像摘要、配置摘要和
状态。所有实例必须返回 `READY` 且摘要完全一致；任一实例解析失败、非 READY 或摘要不同均停止发布。入口的一次响应、
Prometheus 聚合值或单个健康副本不能证明全副本一致。

## 验证范围与剩余门禁

单元测试覆盖摘要格式、输入顺序与时间独立性、key/策略变更敏感性、CLI 安全输出、默认失败关闭、显式迁移放行和错误不
泄漏；集成测试锁定管理员 API 摘要契约；CI 校验 CLI 入口，版本与运维证据契约要求脚本和阶段文档存在。

本阶段不实现跨 Pod 主动抓取、集中式配置分发或自动重启，也不比较 HMAC secret。真实 Kubernetes 逐 Pod 发布演练、真实
Ed25519 私钥切换、旧 key 拒绝观测、生产 Alertmanager 接收器和 OIDC/SPIFFE 联邦验证仍属于外部发布门禁。本地审计 sink
只用于证明 firing/resolved 路由，不能替代生产值班接收器。
