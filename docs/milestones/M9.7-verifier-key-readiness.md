# M9.7 验证器密钥轮换就绪度

## 目标

M9.6.2 已让 Ed25519 verifier key 支持启用、到期与紧急吊销，但运维人员仍需直接阅读启动配置，才能判断当前是否有可接受
key、旧新 key 是否形成重叠窗口，以及哪些 key 即将到期。M9.7 增加只读的生产轮换就绪视图，让 System Admin 在不接触
公钥原文和任何私钥材料的前提下完成重启后检查。

## 就绪度语义

控制面以当前 UTC 时间为统一快照点，将每把 key 分类为 `ACTIVE`、`EXPIRING_SOON`、`NOT_YET_ACTIVE`、`EXPIRED` 或
`REVOKED`。`EXPIRING_SOON` 的窗口由 `SUPPLY_CHAIN_KEY_EXPIRY_WARNING_DAYS` 控制，默认 30 天，启动时只接受 1 至 365。

轮换重叠按 `(verifier, workload_identity)` 逐组计算，不同验证器或不同工作负载身份的 key 不能互相凑数：

- `BLOCKED`：没有配置 Ed25519 key，或全部 key 当前均不可接受；
- `WARNING`：仍有可接受 key，但至少一个身份没有两把可接受 key、存在即将到期 key，或旧 HMAC 兼容入口仍启用；
- `READY`：每个已配置身份均有至少两把当前可接受 key，且没有到期或兼容入口预警。

该状态用于判断轮换窗口，不替代生产 key 必须显式配置 `not_before`/`not_after`、API 节点时钟同步和真实旧 key 拒绝演练。

## API 与隐私边界

`GET /api/v1/admin/supply-chain/verifier-keys` 仅允许 System Admin 调用，返回快照时间、预警窗口、各生命周期计数、重叠
状态、稳定告警代码及按 credential 排序的 key 列表。单 key 只包含 credential、verifier、工作负载身份、SHA-256 指纹、
当前状态和生命周期时间，不返回 32 字节公钥、私钥、HMAC secret、签名 Header 或历史 Envelope。

状态由每个 API 进程的启动配置和当前时间即时计算，不写数据库，因此本阶段不增加 Alembic 迁移。配置变更仍需重启所有
API；多副本发布必须逐实例确认加载了同一公钥环，再以入口流量复核统一结果。

## 管理端

系统管理中心新增“验证器密钥”页签，展示整体就绪状态、已配置/当前有效/待启用/即将到期计数、稳定告警说明，以及每把
key 的身份、指纹和启用/到期/吊销时间。界面通过既有管理员会话访问同一个只读 API，不接收前端环境变量中的 key 材料。

## 验证范围与剩余门禁

单元测试覆盖无 key、单 key、双 key、生命周期计数、到期预警、历史 HMAC，以及不同身份不能构成重叠窗口。集成测试覆盖
System Admin 成功、普通用户 403、已配置双 key 的响应和公钥原文不泄漏；前端严格 TypeScript、版本/部署契约和完整仓库
回归作为阶段门禁。

本阶段不替代真实生产 API 多副本重启、CI 私钥切换、旧 key 到期/吊销拒绝、TLS 入口、Kubernetes 真实集群或 OIDC/SPIFFE
联邦验证。相关操作完成前，生产发布清单中的对应条目保持未勾选。
