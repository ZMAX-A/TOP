# M8.3 质量告警自动评估状态机

## 目标

把 M8.1 的相邻 UTC 窗口质量信号自动接入 M8.2 的可靠 Webhook 队列，同时保持质量分析 GET 请求无副作用，
并覆盖正常结果、排队取消、执行超时和 Runner 失联等全部 Run 终态来源。

## 已实现

- `calculate_quality_comparison` 提供不加载趋势、失败聚类和 Flaky 分析的轻量相邻窗口计算，页面分析与自动评估
  共用同一套 Run、Case 和执行可靠性口径；
- 独立 `quality-alerts` Compose 服务按 `next_evaluation_at` 锁定到期配置，支持可调轮询、评估间隔和批量上限，
  多实例使用 `FOR UPDATE SKIP LOCKED` 避免重复处理；
- 每个项目和指标持久化 `NO_DATA/STABLE/WARNING/CRITICAL` 状态、当前/上一窗口值、信号指纹、通知序号、
  最近转换/通知时间、冷却截止时间和最近投递 ID；
- 首次达到订阅等级产生 `quality.alert.triggered`，WARNING 升为 CRITICAL 产生 `escalated`，严重度下降产生
  `deescalated`，恢复稳定产生 `recovered`；缺少对比数据不错误标记为恢复；
- 升级、降级和恢复不受冷却阻塞；恢复后同等级告警在项目配置的冷却期内被抑制，冷却到期且问题持续时允许
  重新触发；状态行锁、通知序号和唯一投递键共同保证重复评估不重复入队；
- 配置 API 新增 60–86400 秒冷却期及最近/下次评估时间，新增只读状态 API；前端展示三个指标的自动状态、
  百分点变化、活跃通知与评估时间；
- 平台版本统一提升到 `0.18.0`，Alembic Head 提升到 `20260817_0013`。

## 事务与安全边界

- evaluator 只读取平台数据库并在同一事务中更新状态、审计和投递记录，不执行外部 HTTP；真实网络访问仍只由
  `quality-webhooks` dispatcher 完成；
- Webhook 禁用或最低等级变化会清除活跃通知/冷却状态并安排重新评估，不删除历史状态、投递或审计；
- evaluator 更新运行时间不会改写配置更新时间；原始目标 URL 仍不会进入状态 API、自动事件审计或前端；
- 当前自动评估仅覆盖项目级无维度筛选信号。目标、环境、基线级订阅需要先定义独立订阅实体和容量上限，不能
  直接把页面临时筛选扩展为后台任务。

- 全量 Pytest 92 项及仓库标准测试入口 68 项通过；状态机显式覆盖触发、升级、降级、恢复、无数据保持、冷却
  抑制、到期重触发和重复评估幂等；
- Ruff 检查通过，134 个 Python 文件格式一致；Schema 导出与不可变制品摘要检查通过；
- Vue 严格 TypeScript 检查和 Vite `0.18.0` 生产构建通过；
- Alembic 唯一 Head 为 `20260817_0013`，完整离线升级 SQL 生成通过；当前终端没有可用 Docker CLI，因此
  PostgreSQL 17 迁移往返、Compose 全栈、真实 Webhook 接收与浏览器流程仍需在 CI 或验收环境复验。
