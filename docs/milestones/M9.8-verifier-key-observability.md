# M9.8 验证器密钥就绪度指标与告警

## 目标

M9.7 提供 System Admin 主动查看的密钥轮换就绪页，但无法在无人值守时发现所有 key 失效、轮换重叠缺失或旧 HMAC 长期
未关闭。M9.8 将同一就绪快照接入 Prometheus 和固定规则，让值班人员在供应链准入真正中断前获得低基数、可持续评估的
信号。

## 指标

每次通过认证的 `/metrics` 抓取都从当前 API 进程的启动配置和当前 UTC 时间重新计算快照，并更新：

- `testops_supply_chain_key_readiness{status}`：`READY`、`WARNING`、`BLOCKED` 三个固定序列中的 one-hot 状态；
- `testops_supply_chain_verifier_keys{status}`：`ACTIVE`、`EXPIRING_SOON`、`NOT_YET_ACTIVE`、`EXPIRED`、`REVOKED` 五类计数；
- `testops_supply_chain_rotation_overlap_ready`：每个 `(verifier, workload_identity)` 是否都有双 key 重叠；
- `testops_supply_chain_legacy_hmac_enabled`：迁移用 HMAC 入口是否仍启用；
- `testops_supply_chain_key_readiness_snapshot_success`：本次配置快照是否成功。

快照不依赖数据库，因此数据库不可用时仍能反映 API 已加载的公钥环。计算异常只将独立成功指标置 0，不中断其他指标输出。

## 标签与隐私边界

所有新增标签值均为代码固定枚举，不包含 credential、verifier 名、工作负载身份、公钥指纹、项目、用户、Envelope 或事件
ID。身份和指纹继续只在 M9.7 的 System Admin 会话接口中按权限显示；Prometheus 只获得聚合状态，避免敏感元数据扩散和
时序基数随 key 轮换增长。

## 告警

`infra/observability/alerts.yml` 新增五条规则：快照连续失败、没有当前可接受 Ed25519 key、至少一个身份缺少双 key 重叠、
有效 key 进入到期预警窗口，以及历史 HMAC 仍启用。无可接受 key 为 critical；其余为 warning，并使用持续时间抑制重启和
边界时刻的瞬时抖动。

轮换未就绪规则在整体 `BLOCKED` 时不重复触发 warning；值班人员应先恢复至少一把可接受 key，再建立双 key 重叠。告警
规则不自动修改配置、重启 API、延长到期时间或重新启用 HMAC。

## 验证范围与剩余门禁

单元/集成测试覆盖 BLOCKED 与 READY 的 one-hot 指标、生命周期计数、重叠/HMAC 状态、快照异常失败关闭，以及指标文本不
包含 credential 和工作负载身份。部署契约锁定五条告警和所需指标名称；Ruff、全量回归、前端构建、Compose 配置展开和
版本一致性继续作为阶段门禁。

本阶段不包含真实 Prometheus/Alertmanager 接收器、生产测试告警、API 多副本配置漂移检测、真实密钥轮换或 OIDC/SPIFFE
联邦验证；这些项目完成前不能把监控代码通过等同于生产告警闭环完成。
